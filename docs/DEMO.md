# 十分钟演示与提交准备

演示前准备完整 Windows delivery/runtime、一个小的中文文本文件、一个二进制文件和一个空文件。单机使用 127.0.0.1；课堂上按四个窗口展示一个服务器、Alice、Bob、Charlie 三个客户端。先确认 TCP 8888/8889 没有被其他实验实例占用。

## 0 到 2 分钟 基础 TCP

1. 在两个终端分别启动 tcp_basic_server.exe 8888 和 tcp_basic_client.exe 127.0.0.1 8888。
2. 客户端发送“你好，TCP”，服务器显示后输入“已收到”。说明程序按请求、回复交替操作。
3. 客户端输入 /quit，观察双方正常结束。指出 TCP 字节流由四字节大端长度头恢复消息边界。

## 2 到 4 分钟 登录 公共大厅与私聊

1. 双击 start_server.cmd；服务器使用 TCP 8889。
2. 启动三个客户端，分别填 Alice、Bob、Charlie，点击“连接服务器”。确认状态显示“已登录”，在线名单有三人。
3. Alice 在公共大厅发送中文文字，确认 Bob、Charlie 都收到。
4. Alice 发送 /w Bob 这是一条私聊，确认 Alice 与 Bob 看到该消息，Charlie 看不到。
5. 说明昵称登录没有账户密码认证，内部空白昵称和重复在线昵称会被拒绝。

## 4 到 6 分钟 群组与文件

1. Alice 点击“创建群组”，输入“实验讨论组”；Bob 在下拉框选择该群，先展示未加入时无法发送，再点击“加入群组”。Charlie 留在大厅。
2. Alice 向讨论组发送“仅群成员收到”，Bob 收到，Charlie 不收到。
3. Alice 点击“发送文件”，发送准备的小文件。Bob 在保存对话框选择目录后打开或核对原始字节，Charlie 不应收到。
4. 可补发空文件，说明原始文件大小上限 5 MiB。发送者显示“已转发”不等于对方已保存，Bob 的保存结果才表示落盘。

## 6 到 8 分钟 直接 TCP 文字呼叫

1. Alice 在在线列表中选择 Bob，点击“呼叫选中用户”，Bob 展示来电弹窗并点击“接听”。
2. 展示双方独立 TCP 文字窗口，Alice 与 Bob 各发一句中文。
3. 说明服务器先交换信令和被叫临时监听端口，然后主叫连被叫，hello/ready 按 callId 关联；直接文字走新 TCP 连接。
4. Alice 点击“取消／结束呼叫”或关闭文字窗口，确认双方退出会话，再发一句群聊证明聊天室仍可用。
5. 若时间允许，再展示拒接或取消一次。30 秒未接听与 10 秒建连/关联是两个不同超时；不要为了演示等待完整超时影响流程。

## 8 到 10 分钟 抓包与测试结果

1. 打开已保存的本机 loopback pcapng，用 tcp.port == 8888 定位基础流，用 tcp.port == 8889 定位聊天室流；自动测试抓包端口以分析文件为准。
2. 用 tcp.stream eq N 展示一次实际 SYN、SYN/ACK、ACK 和实际关闭过程；按捕获结果解释 FIN/ACK 或 RST。
3. Follow TCP Stream 展示四字节帧头后的 JSON。根据被叫临时端口找到直接 call_chat 所在流，区别于聊天室信令流。
4. 展示 delivery/evidence 中测试日志与运行包检查。QtTest 总数含 init/cleanup，行为测试计数以报告脚本解析后的结果为准。

如果需要自动重现抓包，在源码目录执行 `run_capture.ps1 -SkipBuild -WiresharkDir '本机Wireshark目录'`，它定向捕获基础 18888、聊天室 18889 和被叫临时端口，并更新分析材料；随后重新生成报告。手动捕获则在 Wireshark 选择 Npcap Loopback Adapter，完成基础和 Qt 演示再停止保存。显示过滤器与捕获过滤器不同，输入端口时按对应界面语法操作。没有捕获到的包不能作为已完成的分析证据。
